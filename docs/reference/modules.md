# Módulos — Paperfolio

> Dónde vive cada cosa en el código y qué es responsable de qué.

| Módulo | Responsable de |
|---|---|
| `src/lib/site.ts` | Datos del sitio (`siteConfig`: nombre y descripción) para la metadata y la UI |
| `src/lib/cn.ts` | `cn()`: une clases y descarta las vacías (clases condicionales). No resuelve conflictos de Tailwind (`px-4` y `px-0` quedan las dos) |
| `src/lib/share.ts` | `shareOrCopy()` (Web Share API con caída a copiar el link) y `copyText()` (Clipboard API); no lanzan, devuelven el resultado para que la UI avise |
| `src/lib/gsap.ts` | Registra `ScrollTrigger` y exporta `gsap` y `MOTION_OK` (la consulta de reduced-motion para `gsap.matchMedia`); solo para componentes de cliente |
| `src/lib/env.ts` | Valida con Zod las variables del servidor (`MONGODB_URI`, `MONGODB_DB`; `IP_HASH_SAL` aparte con `leerIpHashSal()`, y `RESEND_API_KEY` con `CONTACTO_EMAIL_DESTINO` con `leerEmailConfig()`, para que la base no las exija) y las expone tipadas (`env`, `leerEnv()`). Los errores nombran la variable, nunca el valor |
| `src/lib/db.ts` | `conectar()`: conexión de Mongoose cacheada en `globalThis`; `desconectar()` la cierra (para tests). Nunca loguea la URI |
| `src/models/Consulta.ts` | Modelo Mongoose de la colección `consultas` (ver [domain.md](domain.md)) |
| `src/app/api/consultas/route.ts` | `POST /api/consultas`: lee la IP, llama a `crearConsulta` y traduce el resultado a HTTP |
| `src/lib/api-error.ts` | `respuestaError(status, codigo, mensaje, extra?)` y `respuestaConfiguracionInvalida()`: el formato único de error de la API (`/api/salud` y `/api/consultas`) |
| `src/lib/ip.ts` | `leerIp(headers)`: primer valor de `x-forwarded-for` o `x-real-ip`; vacío si no hay |
| `src/lib/consultas.ts` | `crearConsulta(input, { ip, avisar? })`: valida con `parseContactRequest`, descarta si el campo trampa `sitio_web` trae algo (antes de validar), corta con `limite` al llegar a 5 consultas por hora del mismo `ipHash` y guarda (si no puede crear los índices de `consultas`, loguea el nombre del error y guarda igual). Devuelve `creada`, `invalida` (errores por campo), `limite` o `descartada`; lanza un error si la `ip` viene vacía. Tras guardar llama a `avisar(consulta)` (por defecto `avisarConsultaNueva`): si sale bien marca `emailEnviado: true`; si falla, la consulta queda con `emailEnviado: false`, se loguea solo el nombre del error y igual devuelve `creada` |
| `src/lib/bandeja.ts` | `parsearFiltros(searchParams)` valida con Zod (lo inválido se descarta; ceros a la izquierda en `pagina` no cuentan) y `listarConsultas({ tipo?, estado?, pagina })` recibe esos filtros ya validados (la página fuera de rango devuelve la última válida, mínimo 1). Devuelve `{ items, total, paginas, pagina }` de a 20, con campos explícitos (`id`, `nombre`, `tipo`, `estado`, `extracto`, `creadaEn`): `ipHash` y `email` no salen de ahí. Crea los índices de `consultas` (`asegurarIndicesDe`; si falla, loguea el nombre del error y sigue). Un estado guardado desconocido o ausente sale como `nueva` (`estadoLeido`) |
| `src/lib/estados-consulta.ts` | Módulo puro (sin base; lo usan el modelo, la bandeja y el cliente): `ESTADOS_CONSULTA`, `ETIQUETAS_ESTADO`, `TRANSICIONES`, `origenesDe(estado)`, `esEstadoConsulta`, `estadoLeido(valor)` (desconocido o ausente → `nueva`), `filtroDeEstados(estados)` (la condición de Mongo coherente con `estadoLeido`) y `LARGO_MAXIMO_NOTA` (2000, para el formulario y el servidor). Los componentes importan de acá, no de `bandeja.ts` (que arrastra Mongoose) |
| `src/lib/seguimiento.ts` | `obtenerConsulta(id)`: el detalle para el panel (con el `email`, sin `ipHash`) y el historial con el nombre de cada autor; `null` si el id no es un ObjectId de 24 hex o no existe. `cambiarEstado(id, estado, autor)` y `agregarNota(id, texto, autor)` validan con Zod y escriben con un solo `updateOne` (estado + entrada en el seguimiento); devuelven `{ ok: true }` o `{ ok: false, error: "no-encontrada" \| "transicion-invalida" \| "invalida", mensaje }` y lanzan si el `autor` no es un id (sale de la sesión) |
| `src/app/panel/consultas/[id]/` | Detalle de una consulta: `page.tsx` (Suspense), `detalle.tsx` (`requerirRol` y después `obtenerConsulta`; 404 si no existe), `controles.tsx` (cliente, `useActionState`; si guardar la nota falla, el texto vuelve en el estado de la acción para no perderlo con el reset del formulario), `acciones.ts` (server actions `cambiarEstadoAccion` y `agregarNotaAccion`, con `requerirRol` cada una y el autor de la sesión; refrescan si salió bien o si la transición fue inválida) |
| `src/lib/proyecto-entrada.ts` | Módulo puro (sin Mongoose; lo usan el servicio, las acciones y el formulario): `proyectoEntradaEsquema` (extiende `proyectoEsquema`, así no se guarda nada que la lectura descarte, como un string vacío en el stack; suma los largos de `LIMITES` y `publicado`), `sugerirSlug(nombre)`, `datosDeFormulario(formData)` (listas por línea, sin las vacías), `valoresDeFormulario`, `valoresDeProyecto` y `erroresPorCampo(issues)` (un mensaje en castellano por campo, `caso.problema` incluido) |
| `src/lib/proyectos-admin.ts` | CRUD de proyectos del panel (#51), sin chequeo de rol (lo hacen las acciones) ni next/cache: `listarProyectosAdmin()` (todos, en orden, con la cantidad de demos), `obtenerProyectoAdmin(id)`, `crearProyecto(datos)` (al final del orden), `actualizarProyecto(id, datos)` (sin `imagen`, la quita), `borrarProyecto(id)` (el proyecto y después todas sus demos; si fallan las demos, `parcial` y la acción invalida el sitio igual; la imagen de Blob queda), `publicarProyecto(id, publicado)` y `reordenar(ids)` (todos los ids, cada uno una vez; si la lista no coincide con la base, `desactualizada` y no cambia nada). Validan con `proyectoEntradaEsquema` antes de escribir; el slug duplicado lo frena el índice único (`asegurarIndicesDe`). Devuelven `{ ok: true, id? }` o `{ ok: false, error: "invalida" \| "no-encontrado" \| "desactualizada" \| "parcial", mensaje, campos? }` |
| `src/app/panel/proyectos/` | Sección de proyectos del panel (solo `admin`): `page.tsx` (lista), `nuevo/page.tsx` y `[id]/` (`page.tsx` con Suspense y `editar.tsx`), cada una con `requerirRol(…, "admin")` antes de leer; `lista.tsx` y `formulario.tsx` (cliente, `useActionState`; la imagen se sube por `fetch` a `/api/imagenes`; un envío fallido remonta los campos con lo mandado); `acciones.ts` (server actions con `requerirRol` cada una; si escriben, `updateTag(TAG_CONTENIDO)` y vuelven a la lista o la refrescan) |
| `src/app/panel/layout.tsx` | Guarda del shell del panel (no de las páginas: cada página y acción llama a `requerirRol` antes de leer datos): `requerirRol("/panel/consultas", "operador", "admin")` dentro de `Suspense` (`auth()` lee cookies) y `PanelShell` (`src/components/panel/`): barra lateral desde 1024 px, barra inferior en celular. El menú muestra las secciones del rol (`enlacesPara(rol)` en `enlaces.ts`, una entrada por sección; solo UI) y `EnlaceActual` (cliente) marca la sección actual |
| `src/lib/email.ts` | `avisarConsultaNueva(consulta, cliente?)`: manda con Resend, desde `onboarding@resend.dev` a `CONTACTO_EMAIL_DESTINO`, un texto plano con asunto `Nueva consulta (<tipo>) de <nombre>` y el email del visitante como `replyTo`. El cliente se inyecta para testear; lanza si falta la config o si Resend responde con error |
| `src/app/api/salud/route.ts` | `GET /api/salud`: health check de la base (ping) |
| `src/components/Container.tsx` | Ancho máximo y márgenes laterales de las secciones |
| `src/lib/contact.ts` | `parseContactRequest()`: valida la consulta del formulario (nombre, email, tipo `general`/`cotizacion`/`asesoria`, mensaje de 10 a 2000 caracteres) y devuelve un error por campo |
| `src/content/profile.ts` | Perfil, stack y trayectoria (estáticos), y los proyectos (con su `caso` de estudio y su `demoUrl`) y servicios iniciales: los carga `npm run seed:contenido` y son el respaldo si la base no responde (ADR-003). Define `SERVICE_ICONS` |
| `src/components/sitio/` | Secciones de la landing (`Sections.tsx`, `Contact.tsx`), `Navbar` (menú de celular: inerte afuera, Escape, se cierra en PC; recibe la sesión como slot), `CuentaBarra` y `MenuCuenta` (Ingresar o avatar con menú: Mi cuenta, Panel, Salir), `StackBand` (banda con pausa), `ContactForm`, `Reveal` (entrada con GSAP ScrollTrigger; sin JS o con reduced-motion se ve fijo), `HeroMotion`, `ShareButton` y `CopyProfileLink`, `Highlight` y `SectionTitle`, `tones.ts` (clases de color por tono) e ilustraciones SVG con tokens |
| `src/auth.ts` | Auth.js v5 con Google y sesión JWT (`handlers`, `auth`, `signIn`, `signOut`). Registra al usuario al ingresar. Ver ADR-002 |
| `src/models/Usuario.ts` | Modelo de `usuarios` y la lista de roles (`ROLES`) |
| `src/lib/usuarios.ts` | `rolParaEmail()`, `registrarIngreso()` (upsert por email con el rol según `ADMIN_EMAILS` y `OPERADOR_EMAILS`) y `buscarRol()` (rol vigente, recalculado con esas listas) |
| `src/lib/acceso.ts` | `evaluarAcceso()`: decide si una sesión alcanza para unos roles, releyendo el rol de la base (`sin-sesion`, `sin-permiso`, `sesion-huerfana`), `rutaInterna()`, `urlDeIngreso()` (la URL de `/ingresar?callbackUrl=…`) y `respuestaSinAcceso(motivo)` (401 `SIN_SESION` o 403 `SIN_PERMISO` en JSON, para las APIs). Lógica pura, sin Next |
| `src/lib/ingreso.ts` | `decidirIngreso({ sesion, error, callbackUrl })` (redirigir o mostrar /ingresar; el `callbackUrl` pasa por `rutaInterna`) y `puedeVerPanel(rol)` (solo UI). Lógica pura |
| `src/lib/sesion.ts` | `sesionParaLaBarra()` (token, sin base; `null` sin sesión o sin variables `AUTH_*`) y `estadoDeSesion()` (`ninguna`, `valida` o `huerfana`, releyendo el rol de la base) |
| `src/lib/sesion-acciones.ts` | Server actions `ingresarConGoogle`, `salir` y `salirEIngresarDeNuevo` |
| `src/lib/permisos.ts` | `requerirSesion(volverA)` y `requerirRol(volverA, rol, ...otros)` (al menos un rol) para páginas y server actions: redirigen a `/ingresar` o responden 403 (`forbidden()`). `requerirRolApi(rol, ...otros)` para route handlers: la misma decisión, sin redirect; devuelve `{ ok: true, id, rol }` o `{ ok: false, respuesta }` con el JSON 401/403 |
| `src/proxy.ts` | Proxy de Next 16: redirige a `/ingresar?callbackUrl=…` si no hay sesión en las rutas protegidas (hoy `/proyectos/:path+`). Solo adelanta la redirección; el control real es `requerirSesion` en cada página |
| `src/lib/proteccion.ts` | `redireccionDeProxy(pathname, haySesion)` y `PREFIJOS_PROTEGIDOS`: la decisión del proxy, pura y testeable |
| `src/lib/proyectos.ts` | `rutaDetalle(slug)`, `rutaDemo(slug)` y `RUTA_PROYECTOS` |
| `src/models/Proyecto.ts`, `Demo.ts`, `Servicio.ts` | Modelos del contenido administrable (ver [domain.md](domain.md)) |
| `src/lib/contenido.ts` | Lectura del contenido para el sitio (ADR-003): `listarProyectos()`, `detalleProyecto(slug)` (proyecto y demos activas en una sola lectura, de la base o del respaldo, nunca mezclados; `buscarProyecto` y `demosDe` lo envuelven) y `listarServicios()`, solo lo publicado o activo y validado. Si la colección está vacía o la base falla, devuelven lo de `profile.ts` (del error se loguea solo el nombre). Las que leen van con `use cache` y `cacheTag(TAG_CONTENIDO)`: `hours` si leyeron de la base, `minutes` si usaron el respaldo. Quien edite el contenido llama a `updateTag(TAG_CONTENIDO)` |
| `src/lib/contenido-esquemas.ts` | Esquemas Zod y tipos públicos del contenido (`Proyecto`, `Demo`, `Servicio`), `esUrlHttps`/`esUrlHttp` (validadores de los modelos) y el paso de `profile.ts` a esa forma (`proyectoDesdePerfil`, `demoDesdePerfil`, `servicioDesdePerfil`) |
| `src/lib/seed-contenido.ts` | `sembrarContenido()`: carga inicial idempotente desde `profile.ts` (inserta solo lo que falta, por `slug` o `titulo`, sin tocar los existentes, ni siquiera `actualizadoEn`; la demo, solo si el proyecto no tiene ninguna) |
| `scripts/seed-contenido.ts`, `scripts/ts-hooks.mjs` | `npm run seed:contenido`: corre el seed con Node (type stripping) y unos hooks que resuelven el alias `@/` y los imports sin extensión. `--env-file` pisa las variables de la shell; imprime host y base (`destinoDelSeed()`) y se niega con Atlas salvo `--atlas` |
| `src/lib/imagenes.ts` | `validarImagen(bytes)`: detecta PNG, JPEG o WebP por la firma y lee el ancho y el alto de la cabecera (IHDR, SOFn, VP8X/VP8L/VP8), sin decodificar ni dependencias extra; rechaza con `motivo` `formato` (incluido SVG), `tamano` (más de 2 MB) o `dimensiones` (más de 2000 px). `subirImagen(bytes, { subir?, generarId? })`: valida, nombra `contenido/<uuid>.<ext>` y sube con acceso público. El cliente de Blob se inyecta en los tests; el real usa `BLOB_STORE_ID` (`leerBlobConfig()` de `env.ts`) |
